# Сервер: GitHub Pages

Игра выложена как статический сайт на GitHub Pages — по HTTPS на адресе
`github.io`. Раньше она лежала и на домашнем сервере (по HTTP на голом IP);
оттуда её убрали 2026-09-18, подробности и вход на сервер — в `_tmp/server.md`.

## Как это устроено

- Собранная игра (`game/dist/`) живёт в **отдельном** репозитории
  `battletech-play`, рядом с этим: `../battletech-play`. Исходники в него не попадают,
  только готовая сборка.
- Ветка — `main`, GitHub Pages включён на «Deploy from a branch → `main` →
  `/ (root)`».
- Адрес: `https://rapulse.github.io/battletech-play/`.
- Всё обновление делает один скрипт — `tools/deploy_play.sh`.

### Почему нет `.github/workflows/deploy.yml`

Файл-автосборщик для GitHub Actions здесь не нужен и не создавался. Такой
workflow собирает игру на серверах GitHub при каждом пуше исходников — но у
проекта `battletech` нет удалённого репозитория, исходники на GitHub не
уходят. Сборку делает `tools/deploy_play.sh` у тебя на машине, а в
`battletech-play` уходит уже готовый сайт, который Pages просто раздаёт.
Если когда-нибудь исходники поедут на GitHub и захочется, чтобы сборка шла
там, workflow добавляется отдельным шагом (сборка `game/` и публикация
`dist/` через `actions/deploy-pages`), а скрипт станет ненужным.

## Как обновить игру

```
tools/deploy_play.sh
```

Скрипт по шагам:

1. собирает игру (`pnpm --dir game build`);
2. `rsync --delete` переносит `game/dist/` в `../battletech-play/`, не трогая
   `.git` (`--delete` убирает чанки со старым хешем в имени);
3. создаёт `.nojekyll` (без него Pages пропускает файлы, начинающиеся с
   подчёркивания, и гоняет сайт через Jekyll);
4. коммитит всё в `battletech-play` с сообщением «Обновление игры <дата>»;
   если изменений нет — коммит пропускается;
5. делает `git push origin main`.

После пуша Pages пересобирает сайт за одну-две минуты. Прогресс видно на
вкладке Actions репозитория `battletech-play`. Открывай сайт с жёстким
обновлением (Cmd+Shift+R), иначе браузер покажет старые чанки.

## Первичная настройка (один раз)

1. Создать на GitHub пустой репозиторий `battletech-play` (без README и
   `.gitignore`, чтобы не было расхождения историй).
2. Локально, рядом с проектом:

   ```
   cd ..   # родительская папка проекта
   mkdir battletech-play && cd battletech-play
   git init -b main
   git remote add origin https://github.com/rapulse/battletech-play.git
   ```

3. Запустить `tools/deploy_play.sh` — он соберёт, закоммитит и отправит.
   Если `origin` не привязан, скрипт сообщит об этом и не пойдёт в пуш.
4. В GitHub: Settings → Pages → Source: «Deploy from a branch», ветка `main`,
   папка `/ (root)`. Сохранить.

Авторизация пуша — обычная для GitHub (SSH-ключ или токен в связке ключей);
скрипт её не настраивает.

## Почему пути относительные

Pages отдаёт сайт не с корня домена, а из подпапки `/battletech-play/`.
Ссылка вида `/ui/factions.jpg` уходит на `github.io/ui/…` и даёт 404. Поэтому:

- `game/vite.config.ts` — `base: './'`, Vite пишет в `index.html` и
  в чанках относительные пути;
- картинки, которые Vite не видит (лежат в `public/ui/`, пути записаны в
  `atlases.json` и `mechArt.json`), склеиваются с `import.meta.env.BASE_URL`
  в `AtlasImage.svelte` и `mechArt.ts`;
- ссылки на вики и «назад в игру» — `./wiki.html`, `./` (обе страницы лежат
  в одной папке, так что `./` верно с любой из них).

**Правило для нового кода:** не пиши в `game/src/` пути и ссылки, начинающиеся
с `/`. Файл из `public/` — через `import.meta.env.BASE_URL`, страница
проекта — `./страница.html`. Абсолютный путь в dev и в корне домена
работает, а на Pages молча ломается — заметишь только после выкладки.

Проверка перед выкладкой: `grep -rnoE 'href="/[^"]*"|"/ui/' game/dist` — в
собранном коде не должно быть ссылок с ведущим `/` (строка `"/ui/…"` внутри
данных допустима, если код склеивает её с `BASE_URL`).

## Если что-то пошло не так

- **Сайт открывается, но без картинок или стилей** — где-то остался
  абсолютный путь (см. правило выше); открой DevTools → Network и найди
  запрос, ушедший на корень `github.io`.
- **Ссылка на вики ведёт на 404** — то же самое, ссылка с ведущим `/`.
- **Пустая страница, 404 на `assets/*.js`** — Pages ещё не пересобрался
  (подожди) или в репозитории нет `.nojekyll` / `index.html` в корне.
- **`Папка ../battletech-play не найдена`** — не сделана первичная настройка.
- **Пуш отклонён (non-fast-forward)** — в `battletech-play` есть коммиты,
  которых нет локально (например, созданный на GitHub README). Подтяни их
  `git -C ../battletech-play pull --rebase origin main` и запусти скрипт
  снова. `--force` не нужен.
- **Скрипт пишет «Нет новых изменений»** — сборка не изменилась, пуш всё
  равно выполнится и просто ничего не отправит.
