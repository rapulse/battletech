# Выкладка игры: GitHub Pages

Игра — статический сайт на GitHub Pages: `https://rapulse.github.io/battletech/`.
Собирает и выкладывает её GitHub Actions из этого же репозитория — файл
[`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml).

## Как обновить игру

Выкладка только **вручную**: push в `main` игру не трогает, так что сырой коммит к игрокам не
уходит. Когда несколько коммитов проверены и отправлены:

1. GitHub → репозиторий `battletech` → вкладка **Actions** → слева **Deploy game**.
2. **Run workflow** → в списке оставить ветку `main` (можно выбрать и другую — выложится она) →
   зелёная кнопка **Run workflow**.
3. Через две-три минуты запуск зеленеет; ссылка на сайт — в шаге `deploy`.

Выкладывается то, что лежит **на GitHub**, а не на ноутбуке: перед запуском — `git push`.

Что делает запуск: берёт выбранную ветку, ставит зависимости по `game/pnpm-lock.yaml`
(`pnpm install --frozen-lockfile`), собирает `pnpm build` и публикует `game/dist/`. Тесты в нём
не гоняются — проверка остаётся за `pnpm check` до push.

Открывай сайт с жёстким обновлением (Cmd+Shift+R), иначе браузер покажет старые чанки.

## Настройка (один раз)

GitHub → репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Без этого шаг `deploy` падает с ошибкой про Pages.

## Почему пути относительные

Pages отдаёт сайт не с корня домена, а из подпапки `/battletech/`.
Ссылка вида `/ui/factions.jpg` уходит на `github.io/ui/…` и даёт 404. Поэтому:

- `game/vite.config.ts` — `base: './'`, Vite пишет в `index.html` и
  в чанках относительные пути;
- картинки, которые Vite не видит (лежат в `public/ui/`, пути записаны в
  `atlases.json` и `mechArt.json`), склеиваются с `import.meta.env.BASE_URL`
  в `AtlasImage.svelte` и `mechArt.ts`;
- ссылки на вики и «назад в игру» — `./wiki.html`, `./` (обе страницы лежат
  в одной папке, так что `./` верно с любой из них).

**Правило для нового кода:** не пиши в `game/src/` пути и ссылки, начинающиеся
с `/`. Файл из `public/` — через `import.meta.env.BASE_URL`, страница
проекта — `./страница.html`. Абсолютный путь в dev и в корне домена
работает, а на Pages молча ломается — заметишь только после выкладки.

Проверка перед выкладкой: `grep -rnoE 'href="/[^"]*"|"/ui/' game/dist` — в
собранном коде не должно быть ссылок с ведущим `/` (строка `"/ui/…"` внутри
данных допустима, если код склеивает её с `BASE_URL`).

## Сохранения игроков

Сохранения лежат в IndexedDB браузера, а она привязана к домену `rapulse.github.io`, не к пути.
Поэтому переезд с прежнего адреса `/battletech-play/` на `/battletech/` сохранения не теряет.

## Если что-то пошло не так

- **Шаг `deploy` красный, ошибка про Pages или environment** — не сделана настройка выше.
- **Шаг `pnpm install` красный** — lock-файл не совпадает с `package.json`: локально
  `pnpm install`, закоммитить `game/pnpm-lock.yaml`, push, запустить снова.
- **Шаг `pnpm build` красный** — сборка падает и локально: `cd game && pnpm build`.
- **Предупреждение об устаревшей версии action** в журнале запуска — поднять номер версии
  (`@v5` → `@v6` и т.п.) у названного action в `deploy.yml`.
- **Сайт открывается, но без картинок или стилей** — где-то остался
  абсолютный путь (см. правило выше); открой DevTools → Network и найди
  запрос, ушедший на корень `github.io`.
- **Ссылка на вики ведёт на 404** — то же самое, ссылка с ведущим `/`.
